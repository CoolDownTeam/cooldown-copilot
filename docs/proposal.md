## 1. 앱 한 줄 소개

평소의 나를 학습한 AI가 운전이 거칠어지면 실내를 식혀 주고, 졸음은 실내 공기로 미리 막고 조향으로 잡아 실제로 쉬게 만드는 무상호작용 코파일럿.

## 2. 기획 배경

**운전 중 가장 위험한 두 상태는 "화난 운전"과 "졸린 운전"이다.**
- 고속도로 사망사고의 약 70%가 졸음운전과 주시태만 때문에 일어난다. 한국도로공사에 따르면 최근 3년간 이 비율은 71.5%였다.
- 보복운전으로 검찰에 송치된 건수는 2022년 1,570건에서 2025년 1,726건으로 3년 연속 늘었다. 경찰청 자료이며, 단속되지 않은 분노 운전은 이보다 훨씬 많다.

**하지만 지금의 차는 두 상태 모두에 대해 운전자가 스스로 알아채고, 스스로 대처하기를 기대한다.**
- 화가 난 운전자는 자신이 거칠게 운전하고 있다는 사실을 잘 알아채지 못한다.
- 졸린 운전자는 자기 졸음을 모르고, 알아도 쉬지 않는다. 장거리 모의 주행 연구에서 스스로 졸음이 "낮다"고 답한 경우의 75%가 실제로는 중간 이상 졸렸고, 스스로 매우 졸리다고 답해도 75% 넘게 휴게소를 지나쳐 계속 달렸다 (Gaspar & Carney, 2023).
- 기존 운전 점수 앱은 모든 운전자에게 같은 기준을 쓴다. 그래서 원래 시원시원하게 운전하는 사람에게는 계속 경고를 주고, 조심스럽게 운전하는 사람의 변화는 놓친다.
- 경고음과 화면 알림은 운전자의 주의를 빼앗고, 화난 운전자에게는 반감만 키운다.

**차는 이미 답을 알고 있다.**
- 차는 속도, 브레이크, 조향 데이터로 운전자의 상태를 읽을 수 있다. 졸리면 조향의 작은 보정이 줄어든다는 것은 연구로 정리되어 있다 (Sahayadhas 외, 2012).
- 실내 환경은 운전에 영향을 준다. 실내 27℃에서는 21℃보다 놓친 신호가 50% 늘고 반응 시간이 22% 길어졌다 (Wyon 외, 1996). 내기순환을 오래 쓰면 탑승자가 내쉰 CO2가 쌓이고 (Hudda & Fruin, 2018), CO2 1,000ppm부터 의사결정 능력이 떨어진다 (Satish 외, 2012).
- 단, 찬 바람으로 졸음을 깨울 수는 없다. 효과는 잠깐뿐이고, 졸음에 실제로 듣는 것은 짧은 낮잠과 카페인이다 (Reyner & Horne, 1998; Horne & Reyner, 1996).
- 그래서 이 앱은 **말을 걸지 않고 공기로 먼저 대응하되, 졸음에 대해서는 공기로 "예방"하고, 조향으로 "감지"하고, 한마디로 "쉬게" 만든다.**

## 3. 앱 주요 기능 및 차량 특화 요소

| 기능 | 무엇을 하나 | 차량 데이터·제어 |
|---|---|---|
| **AI 운전 패턴 엔진** (공통) | 처음 5번(합계 60분 이상)의 주행으로 이 운전자의 평소 가감속·제동·조향 패턴을 속도대별로 학습하고, 그 뒤로는 "평소와 얼마나 다른지"로 공격성과 피로를 판단한다. 학습은 5번으로 끝나지 않고 주행이 끝날 때마다 계속 갱신해, 운전 습관이 바뀌면 기준도 따라간다. 개입이 일어난 구간은 학습에서 빼서, 화난 운전이 "평소"가 되지 않게 한다 | 차속, 브레이크, 조향각, 기어 |
| **쿨다운 캐빈** | 운전이 평소보다 거칠어지면 한 문장으로 알리고 설정 온도를 1~2℃ 낮추고 바람을 한 단계 올린다. 안정되면 원래 설정으로 되돌린다. 운전자가 공조를 직접 만지거나 "추워"라고 하면 바로 양보하고, 다음부터 그 계절의 강도를 낮춘다 | 공조 온도·풍량·풍향·통풍시트, 외기온, 음성 |
| **피로 케어** | **① 예방:** 내기순환이 탑승 인원에 비해 오래 이어지면 말없이 외기로 바꿔 CO2가 쌓이지 않게 한다. **② 감지:** 장거리에서 조향의 작은 보정이 평소보다 줄고 핸들을 오래 가만히 두면 졸음 신호로 본다. **③ 휴식 유도:** "12km 앞 휴게소에서 잠깐 쉬어 갈까요?" 한마디에 "응"이면 입구 전에 다시 알려 주고, 도착하면 커피 한 잔이나 15분 낮잠을 권한다. 휴게소까지는 시원한 바람으로 버티게 한다 | 조향각, 연속 주행 시간, 내·외기 상태와 전환, 좌석 탑승, 내비 회전 안내(경로 위 휴게소), 음성 |
| **코스 브리핑** | 출발 전 P단에서 경로의 어려운 구간(연속 분기, 복잡한 교차로, 정체 진입)을 30초 음성으로 예습시킨다. 주행 중에는 그 지점 1km 전에 한 문장만 말한다 | 내비 회전 안내(TBT), 정체 구간, 음성 합성 |
| **주행 리포트** | 도착 후 P단에서 오늘의 안정도, 개입 기록("14:32에 3분간 시원하게 해 드렸어요"), 어려운 구간 통과 결과, 최근 추세를 보여준다 | 주행 기록 |

**차량 특화 요소**
- **휴대폰으로는 할 수 없는 실내 제어:** 운전자의 상태에 맞춰 공조를 자동으로 바꾼다.
- **사람마다 다른 기준:** 같은 급제동이라도 이 운전자에게 평소 있는 일인지, 이례적인 일인지를 구분한다.
- **주행 중 무상호작용:** 주행 중에는 터치 입력과 화면 확인을 요구하지 않는다. 출력은 무음 공조 제어, 또는 음성 한 문장뿐이다.
- **투명성:** 개입하는 순간에는 말하지 않지만, 숨기지도 않는다. 처음 쓸 때 동의를 받고, 개입한 기록은 도착 후 리포트에서 모두 알려준다.

**이미 있는 기능과 다른 점** (2026-11-10 조사. 차종별 탑재 여부는 확인 필요)

| 기존 기능 | 그 기능이 하는 일 | 이 앱이 더하는 것 |
|---|---|---|
| Gleo AI 음성 공조 | "너무 더운데?"라고 말하면 조절 | 말하지 않아도 운전 패턴 변화로 먼저 조절. Gleo는 "추워" 피드백 통로로 함께 쓴다 |
| 운전자 주의 경고(DAW) | 주의 수준이 떨어지면 경고·휴식 권유 | 경로 위 실제 휴게소 제안 → "응" → 입구 전 재안내 → 휴식법 권유, 도착까지 공조로 버티기 |
| 자동 외기 전환 (기아 매뉴얼: 에어컨 내기순환 약 30분 후 외기) | 시간·온도 기준 자동 전환 | 차량 자동 기능이 켜져 있으면 맡긴다(F3-P7). 없을 때 탑승 인원 기준으로 보완하는 보조 기능으로만 내세운다 |
| 기아 READ (CES 2019 콘셉트) | 생체 센서로 감정 인식 → 실내 제어 | 카메라·생체 센서 없이 기존 차량 신호만, 앱 설치만으로 동작 |

## 4. 주요 사용 시나리오

### 시나리오 A — 퇴근길 정체 (매일)
**페르소나:** 30대 직장인. 퇴근길 40분 정체 구간을 매일 지나고, 늦어지면 운전이 거칠어지는 편.

1. 앱은 지난 2주 동안 이 운전자의 평소 퇴근길 운전 패턴을 학습해 두었다.
2. 오늘은 회의가 늦게 끝났다. 정체 속에서 급출발과 급제동이 평소보다 잦아지고, 가속과 제동을 신경질적으로 오간다.
3. 공격성 점수가 30초 동안 임계값을 넘는다. 차는 아무 말 없이 설정 온도를 24℃에서 23℃로 낮추고 바람을 한 단계 올린다.
4. 2분 뒤에도 운전이 거칠다. 온도를 22℃로 한 번 더 낮춘다.
5. 운전이 안정되고 5분이 지나자, 1분에 걸쳐 원래 설정인 24℃로 돌아간다.
6. 집 앞에서 P단에 넣으면 리포트가 뜬다. "18:52에 4분간 시원하게 해 드렸어요. 이번 주 퇴근길 중 가장 차분하게 마무리했어요."

### 시나리오 B — 주말 장거리 (가끔)
**페르소나:** 같은 운전자. 주말에 처음 가는 지방 여행지로 2시간 30분을 운전한다.

1. **출발 전:** 목적지를 정하고 P단 상태에서 브리핑을 듣는다. "오늘 길은 2시간 30분이에요. 40km 지점에서 분기가 두 번 연속 나와요. 두 번째는 오른쪽 2차로로 가세요."
2. **분기 1km 전:** "곧 그 연속 분기예요, 오른쪽 2차로." 한 문장뿐이다.
3. **출발 30분째:** 에어컨을 내기순환으로 계속 쓰고 있다. 차는 말없이 5분 동안 외기를 들였다가 다시 내기순환으로 돌린다. 운전자는 알아채지 못한다.
4. **1시간 50분째:** 운전자는 아직 괜찮다고 느끼지만, 조향의 작은 보정이 평소보다 확 줄고 핸들을 가만히 두는 시간이 길어진다. 차는 말없이 얼굴 쪽으로 시원한 바람을 보낸다.
5. **10분 뒤에도 피로 신호가 계속된다:** "12km 앞 휴게소에서 잠깐 쉬어 갈까요?" 운전자가 "응"이라고 답하자 "좋아요, 입구 전에 알려 드릴게요." 1km 전에 "곧 휴게소 입구예요."
6. **휴게소에서 P단:** "커피 한 잔이나 15분 낮잠이 졸음에 가장 잘 들어요." 리포트에는 "실내 공기를 2번 바꿔 드렸어요, 피로 신호가 보여 휴게소를 권했어요"가 남는다.

## 5. 개발 계획

### 구현 범위 (공모전 제출 버전)

| 모듈 | 내용 |
|---|---|
| 차량 데이터 계층 | 차속·기어·브레이크·조향·주행 거리를 Coroutines `StateFlow`로 수집 |
| AI 운전 패턴 엔진 | 1초 단위 특징 추출(급가속, 급감속, 조향 변화율, 가감속 반전), 속도대별 기준선 학습(지수이동평균), 공격성·피로 점수 계산. 모든 계산은 온디바이스 |
| 공조 제어기 | 설정 저장 → 단계적 조절 → 복원. 운전자 조작 감지, 변화 폭과 빈도 상한 |
| 내비 연동 | 회전 안내·정체, 경로 위 휴게소, 어려운 구간 추출 |
| 음성 | 브리핑과 한 문장 안내(TTS), "응/아니" 응답 인식(STT) |
| 정차 화면 | 온보딩·동의, 주행 리포트, 기록, 설정 |

### SDK / API 사용 계획

Pleos API 정책("AAOS에 같은 기능이 있으면 AAOS를 따른다")에 맞춰, AAOS 표준 API를 먼저 쓰고 AAOS에 없는 기능만 Pleos SDK로 구현한다.

| 기능 | API | 출처 |
|---|---|---|
| 차속 | `CarPropertyManager` `PERF_VEHICLE_SPEED` | AAOS 표준 |
| 기어 | `Vehicle.getGear().registerGearSelection` | Pleos Vehicle SDK |
| 브레이크 페달 | `Vehicle.getBrake().registerBrakePedalStatus` | Pleos Vehicle SDK |
| 조향각 | `Vehicle.getSteeringWheel().registerSteeringWheelAngle` | Pleos Vehicle SDK |
| 공조 조회·제어 | `HVAC.get/setHvacTemperature`, `get/setHvacFanSpeed`, `setHvacRecirculation`, `register*` (운전자 조작 감지) | Pleos Vehicle SDK |
| 지원 여부 확인 | `checkHvacTemperatureCapabilities` 등 도메인별 `checkXXXCapabilities` | Pleos Vehicle SDK |
| 회전 안내·정체 | `NaviHelperEventListener.onTBTInfo`, `TrafficCongestionInfo` | Pleos NaviHelper SDK |
| 경로 위 휴게소 | `NaviHelper.getTBTInfo` (`TURN_RESTAREA`) | Pleos NaviHelper SDK |
| 음성 안내·인식 | TextToSpeech SDK, SpeechToText SDK | Pleos SDK |

### AI 설계

| 판단 | 방식 | 이유 |
|---|---|---|
| 개인 기준선 학습 | 속도대별 특징 분포를 주행마다 지수이동평균(α=0.2)으로 갱신. 처음 5회·60분 동안은 기본 기준으로 판단하며 배우고, 그 뒤에도 매 주행 계속 갱신. 개입 구간과 그 앞 3분은 갱신에서 제외 | 운전자마다 다른 "평소"를 기준으로 삼기 위해 |
| 공격성·피로 점수 (실시간) | 기준선 대비 편차(z-score)의 가중합, 온디바이스 | 주행 중에는 지연과 네트워크 의존이 없어야 함 |
| 반응 학습 | "추워"·직접 조작·무반응으로 계절별 강도와 개인 기준 온도를 조정 | 틀린 개입을 다음 주행에서 줄이기 위해 |
| 효과 측정 | 쿨다운 시작부터 공격성이 40 아래로 돌아오기까지의 시간을 기록하고 평소와 비교해 리포트에 표시 | "식혀 주면 차분해지는가"를 운전자별 데이터로 확인하기 위해 |

- 역할 분담: Gleo AI는 운전자가 말한 것을 이해하고, 이 앱은 말하지 않은 상태를 판단한다. 주행 중 판단에는 대형 모델을 쓰지 않는다(지연·네트워크·안전).
- **안내 문장은 LLM이 아니라 템플릿으로 만든다.** 주행 중 음성은 운전자가 듣고 바로 행동해야 하는 한 문장이라 정해진 순간에 바로 나와야 한다.
  - 클라우드 LLM은 응답에 수 초가 걸리고, 터널·산간처럼 통신이 끊기는 구간에서는 아예 오지 않을 수 있다. "곧 연속 분기예요"가 분기를 지난 뒤에 나오면 안내가 아니라 방해다.
  - 생성 문장은 길이와 표현을 보장할 수 없어 "한 번에 한 문장, 탓하지 않는 표현"(SAFE-02) 같은 안전 규칙을 지키기 어렵다.
  - 그래서 상황별 템플릿에 거리·휴게소 이름 같은 값만 채워 네트워크 없이 차 안에서 바로 말하고, 문장은 단위 테스트로 고정했다.
  - LLM은 정차 중 리포트 문장처럼 늦어도 되는 곳에만 확장한다(실패하면 템플릿).

### 안전 설계
- 앱 카테고리는 게임이 아닌 주행 보조로 등록한다. 심사 가이드상 게임은 미디어 앱으로 분류되어 주행 중에 쓸 수 없다.
- 주행 중 화면에는 입력 UI를 두지 않는다.
- 공조 변화 폭은 원래보다 최대 -2℃(절대 최저 18℃), 바람 +1단으로 제한하고, 복원한 뒤 15분 동안은 다시 개입하지 않는다.
- 앞유리 김서림 제거(DEFROST) 중에는 풍향을 바꾸지 않는다. 풍향은 주행 중 2초마다 다시 읽어 운전자 조작을 알아챈다.
- 운전자가 공조를 직접 조작하면 즉시 개입을 멈추고, 그 주행 동안은 다시 개입하지 않는다.
- Vehicle SDK 제어 권한은 Pleos App Market의 사전 승인을 받아 사용한다. `[CONTROL_CAR_CLIMATE 승인 가능 여부 확인 필요]`

## 6. 기대효과 및 발전 가능성

### 사용자 가치
- **안전:** 분노 운전과 졸음운전이 이어지는 시간을 줄인다. 두 가지는 고속도로 사망사고의 가장 큰 원인이다.
- **존중:** 경고하거나 가르치지 않는다. 사람마다 다른 기준을 쓰고, 운전자의 조작을 언제나 우선한다.
- **자기 이해:** 내 운전이 언제, 어떤 길에서 흔들리는지 정차 후 리포트로 알 수 있다.

### 타깃 고객

| 세그먼트 | 니즈 | 사용 빈도 |
|---|---|---|
| 정체 구간 출퇴근 운전자 | 매일 반복되는 정체 스트레스 | 매일 (Retention의 핵심) |
| 주말·출장 장거리 운전자 | 졸음, 낯선 길 | 주 1회 내외 |
| 운전 경력 3년 이하 | 어려운 구간에 대한 사전 준비 | 수시 |

### 지표 목표 `[가정 — 수치 근거 보강 예정]`

| 단계 | 가정 | 근거 |
|---|---|---|
| 설치 | Pleos Connect 탑재 차량의 N% `[탑재 대수 확인 필요]` | — |
| 활성(MAU) | 설치자의 70% | 설치 후에는 주행할 때마다 자동으로 동작하므로, 앱을 일부러 켤 필요가 없음 |
| 4주 Retention | 50% | 사용 빈도가 곧 주행 빈도. 출퇴근 운전자는 매일 사용 |
| 효과 지표 | 쿨다운 뒤 평소 수준으로 돌아오기까지 걸린 시간 (리포트에 표시), 휴게소 제안 수락률, "추워" 비율 | 앱 안에서 측정함 |

### 향후 확장
1. **효과로 배우는 개입:** 개입했을 때와 안 했을 때의 회복 시간을 비교해, 그 운전자에게 효과 있는 수단만 남긴다
2. **차량 안전 기능 연동:** 차량 DAW 주의 수준 신호와 조향 기반 피로 점수를 합친다
3. **동승자·전기차:** 좌석별 공조로 운전석만 식히고, 전기차에서는 냉방 에너지를 주행 가능 거리와 함께 고려한다
4. **정차 중 LLM 문장:** 리포트·브리핑 문장을 정차 중에만 LLM으로 생성 (실패 시 템플릿)
5. **키즈 세이프 캐빈:** 뒷좌석 착석 감지로 도착 후 "뒷좌석 확인" 알림 (차내 아동 방치 사고 예방)
6. **웨더 프리셋:** 경로의 날씨 예보와 와이퍼 상태로 김서림 방지와 전조등을 미리 세팅
7. **가족 리포트:** 고령 부모님 차의 주행 추세를 주간 요약해 가족에게 전달
8. **보험 연계:** 기준선 대비 안정도 지표를 운전 습관 연계 보험(UBI) 할인 근거로 활용
